# Карточка продукта

| Поле | Значение |
|---|---|
| Номер | 204 |
| Название | Библиотека вещей для офиса |
| Репозиторий | `office-lending-library` |
| Профиль | приложение с сервером: FastAPI + SQLite + React, Docker Compose |
| Версия | 1.0.0 (четвёртая партия, 2026-11-21) |

## Аудитория и задача

Офис, где есть общая полка с книгами, переходниками и настольными играми. Сейчас вещи берут «на доверии», и через месяц никто не помнит, у кого переходник USB-C → HDMI. Сотруднику нужно быстро понять, есть ли свободный экземпляр, и взять его без переписки. Куратору полки нужно видеть, что у кого и что просрочено, и вести каталог.

## Сценарий

1. Сотрудник ищет вещь по названию или автору, фильтрует по категории и наличию. В списке сразу видно «в наличии 1 из 2» или «нет в наличии · ближайший возврат 26 ноября».
2. В карточке вещи — физические экземпляры с инвентарным номером, местом хранения и статусом. Кнопка «Взять на 14 дней» оформляет выдачу со сроком.
3. Если двое нажали одновременно, выдачу получает один. Второй видит конфликт, а карточка обновляется до актуального состояния.
4. Вкладка «Мои выдачи» — что у меня и до какого числа. Возврат одной кнопкой.
5. Куратор видит «Просрочки» (кто, что, на сколько дней), принимает вещи, добавляет вещи и экземпляры, списывает и возвращает в фонд. «Журнал» хранит все операции с автором и временем.

## Функции версии 1.0

- Каталог с поиском по названию и автору (без учёта регистра и ё/е), фильтрами по категории и наличию. Список грузится по 100 строк, дальше кнопка «Показать ещё».
- Карточка вещи: экземпляры, место, статус, срок возврата. Заёмщик виден только куратору и самому заёмщику.
- Выдача и возврат с проверкой в транзакции и уникальным индексом на открытую выдачу экземпляра.
- Мои выдачи, просрочки, журнал операций.
- Для куратора: новая вещь, правка, новый экземпляр, списание и возврат в фонд.
- Две роли: сотрудник и куратор. Вход по логину и паролю, сессия в HttpOnly-cookie.
- Docker-контейнер, том для базы, демоданные и синтетика для замеров.

## Практический результат

В демо: 12 вещей, 14 экземпляров, 3 выдачи, одна из них просрочена. Параллельная выдача одного экземпляра проверена 8 одновременными запросами: ровно одна выдача и одно событие в журнале. На 20 000 вещей список отвечает за 9 мс, поиск за 14–15 мс (сервер, медиана замера).

## Границы текущей версии

- Нет очереди и бронирования на будущее: взять можно только свободный экземпляр.
- Нет уведомлений о просрочке (почта, мессенджер). Куратор видит их во вкладке.
- Нет продления срока: вещь возвращают и берут заново.
- Регистрации через интерфейс нет. Пользователей создаёт администратор командой `python -m app.users`.
- Один экземпляр сервера: SQLite не рассчитан на несколько реплик с общим диском.
