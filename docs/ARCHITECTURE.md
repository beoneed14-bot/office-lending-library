# Архитектура 204 · office-lending-library

## Схема

```
Браузер (React SPA, вкладки в адресе #catalog, #item/<id>, #mine, #overdue, #journal)
   │  fetch /api/*, cookie ol_session (HttpOnly, SameSite=Lax)
   ▼
FastAPI (uvicorn, один процесс)
   ├─ web.py      вход, сессии, роли, /api/health, /api/demo/*
   ├─ main.py     маршруты и права (сотрудник / куратор), модели запросов Pydantic
   └─ service.py  правила: поиск, наличие, выдача, возврат, просрочки, журнал
   ▼
SQLite (WAL, foreign_keys=ON), файл /data/office-library.sqlite3 в томе library-data
```

Один контейнер: интерфейс собирается на этапе `node:22-alpine` и раздаётся тем же FastAPI из `/app/static`. Порт опубликован только на `127.0.0.1:8204`.

## Модель данных

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `users` | сотрудники и кураторы | `role IN ('employee','curator')`, уникальный `username` |
| `sessions` | токены входа | случайный токен 256 бит (`secrets.token_urlsafe`), срок жизни |
| `items` | позиция каталога: название, категория, автор или описание, срок выдачи в днях | `category IN ('book','adapter','game')`, `loan_days BETWEEN 1 AND 90`; `title_key`, `search_key` для поиска |
| `copies` | физический экземпляр: инвентарный номер, место | уникальный `code`; `retired_at` — списан |
| `loans` | выдача: кто, когда, до какого числа, когда вернули и кто принял | **частичный уникальный индекс `loans_one_open_per_copy ON loans(copy_id) WHERE returned_at IS NULL`** |
| `events` | журнал: выдача, возврат, правки каталога, экземпляры | `kind` из фиксированного списка, автор и время |

Наличие не хранится, а вычисляется: экземпляр свободен, если он не списан и у него нет выдачи с `returned_at IS NULL`. Просрочка тоже вычисляется: открытая выдача с `due_at` раньше текущего момента. Так нет второго источника правды, который мог бы разойтись с выдачами.

Индексы: `items_category(category, title_key)`, `items_title(title_key, id)` для сортировки каталога, `loans_user`, `loans_open_due` для «моих выдач» и просрочек.

## API

| Метод и путь | Кто | Что делает |
|---|---|---|
| `GET /api/items?q&category&available&limit&offset` | все | каталог: `total` и страница строк с числом экземпляров, свободных и ближайшим возвратом |
| `GET /api/items/{id}` | все | карточка: вещь и экземпляры со статусом `available`, `on_loan`, `retired`, сроком и признаком «мой». Заёмщика видят только куратор и сам заёмщик |
| `POST /api/items`, `PATCH /api/items/{id}` | куратор | новая вещь, правка |
| `POST /api/items/{id}/copies`, `PATCH /api/copies/{id}` | куратор | новый экземпляр (409 `code_taken`), списание и возврат в фонд (409 `copy_on_loan`) |
| `POST /api/loans {copy_id}` | все | выдача себе. 201 — новая, 200 — уже у вас, 409 `copy_taken` или `copy_retired` с актуальной карточкой в поле `card` |
| `POST /api/loans/{id}/return` | заёмщик или куратор | возврат. Повтор отвечает текущим состоянием с `changed=false` |
| `GET /api/loans?status=active|overdue|returned|all&mine` | все | сотрудник видит только свои, куратор все |
| `GET /api/events` | куратор | журнал операций |
| `GET /api/categories`, `/api/me`, `/api/auth/*`, `/api/health` | — | справочник, текущий пользователь, вход и выход, готовность |

Ошибки предметной области — JSON `{"code", "message", "field"?, …}` (409 выдачи — `{"code", "message", "card"}`). Ошибки валидации Pydantic (422) интерфейс раскладывает по полям формы.

## Выдача и возврат (ядро)

```
POST /api/loans {copy_id}
  BEGIN IMMEDIATE
    экземпляр списан?                         → 409 copy_retired
    открытая выдача есть и она моя?           → 200, та же выдача (повтор)
    открытая выдача есть и она чужая?         → 409 copy_taken + карточка
    INSERT loans (...)                        ← уникальный индекс: вторая открытая выдача невозможна
    INSERT events (kind='issue')
  COMMIT
```

`BEGIN IMMEDIATE` сериализует пишущие транзакции, поэтому проверка и вставка не перемешиваются с параллельным запросом. Индекс — вторая линия: даже код, обошедший `service.issue`, не создаст две открытые выдачи (`test_recovery.py` проверяет это вставкой напрямую в базу). `IntegrityError` на индексе превращается в тот же 409 `copy_taken`.

Возврат идёт в той же транзакции `BEGIN IMMEDIATE`: если у выдачи уже есть `returned_at`, ответ с текущим состоянием и `changed=false`, события нет. Иначе `UPDATE loans SET returned_at, returned_by` и событие `return`. Поэтому повтор возврата из второй вкладки не дублирует запись в журнале.

## Поиск

`title_key` = название в нижнем регистре с заменой ё→е и схлопнутыми пробелами. `search_key` = то же для названия и автора. Ключи считаются в Python при записи: функция `lower()` в SQLite меняет регистр только у латиницы, и поиск «макконнелл» по автору «Стив Макконнелл» без этого ничего не находил (находка раунда 1). Запрос каталога сначала выбирает `id` страницы (`ORDER BY title_key, id LIMIT/OFFSET`), затем считает экземпляры и ближайший возврат только для этих `id` (находка раунда 4).

## Интерфейс

- Каталог: поиск с задержкой ввода 250 мс, категория, «Только в наличии», счётчик «Найдено: N», по 100 строк и кнопка «Показать ещё» с переводом фокуса на первую новую строку.
- Карточка вещи: при открытии фокус на заголовке. Кнопка «Взять на N дней», при 409 — баннер «… Карточка обновлена.» и карточка из ответа сервера. У куратора — «Списать», «Вернуть в фонд», форма нового экземпляра.
- «Мои выдачи», «Просрочки» (куратор), «Журнал» (куратор). Срок пишется словами: «просрочено на 4 дня», «сегодня последний день», «вернуть завтра, 22 ноября».
- Потеря сессии (401) возвращает на вход с пояснением. Недоступный сервер — понятное сообщение вместо пустого экрана.

## Решения и причины

| Решение | Причина |
|---|---|
| Частичный уникальный индекс вместо флага «выдан» в `copies` | защита от двойной выдачи на уровне базы, а наличие не может разойтись с выдачами |
| Повтор выдачи и возврата отвечает 200 без новой записи | потерянный ответ и повторный клик не портят журнал |
| В 409 сразу актуальная карточка | интерфейсу не нужен второй запрос, пользователь сразу видит, кто опередил и когда вернут |
| Ключи поиска в Python | корректный регистр для кириллицы и ё/е без расширений SQLite |
| Stdlib `sqlite3` без ORM | маленькая схема, явные транзакции `BEGIN IMMEDIATE` |
| Один контейнер, порт на `127.0.0.1` | простой запуск одной командой, демо не торчит в сеть |
