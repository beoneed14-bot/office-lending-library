# Приёмка 204 · office-lending-library

## Как повторить проверки

```bash
docker compose up -d --build                      # http://127.0.0.1:8204, дождаться healthy
python3 scripts/container_check.py --restart      # готовность, входы, 8 параллельных выдач, повторный возврат, перезапуск

cd backend && python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest                                  # 13 тестов

cd ../frontend && npm ci
npm test                                          # 3 теста Vitest
npm run build
npm run e2e:install && npm run e2e                # 11 сквозных тестов против контейнера (+1 замер, пропускается без синтетики)
docker compose exec app python -m app.synthetic 20000 && npx playwright test e2e/perf.spec.ts
npm run e2e:local                                 # те же тесты без Docker (uvicorn из backend/.venv на :8304)
```

## Окружение проверки

| Компонент | Версия |
|---|---|
| ОС | Linux (облачная песочница), 2 ядра, 7 ГБ |
| Docker / Compose | 29.10.0 / 5.7.1 |
| Образы | `python:3.12-slim`, `node:22-alpine` |
| Python (тесты на хосте) / в образе | 3.13.18 / 3.12 |
| FastAPI / Starlette / Pydantic / uvicorn | 0.165.0 / 1.10.0 / 2.14.4 / 0.54.0 |
| Node.js / npm | 22.23.5 / 10.9.9 |
| React / Vite / TypeScript / Vitest / Playwright | 19.3.1 / 8.3.8 / 7.0.2 / 5.1.1 / 1.65.1 |

**Особенность окружения.** Песочница перехватывает исходящий TLS прокси с собственным корневым сертификатом, поэтому `docker compose up -d --build` здесь падает на `pip install` с `certificate verify failed`. Dockerfile принимает необязательный секрет сборки `extra_ca`, и в песочнице образ собирался так: `docker build --secret id=extra_ca,src=<ca-bundle> -t office-lending-library:local . && docker compose up -d`. Это путь README для корпоративного прокси. Без секрета сборка не меняется. Обычная `docker compose up -d --build` в этой песочнице не проверена.

## Раунд 1. Правила и полнота продукта

Сверка с ТЗ: каталог и экземпляры раздельно (`items`, `copies`), наличие по экземплярам без открытой выдачи, просрочка по сроку открытой выдачи, возврат закрывает запись фактическим временем, контракты `GET /items`, `POST /loans`, `POST /loans/{id}/return`, `GET /loans?status=overdue` есть, автор берётся из сессии, уникальный индекс на открытую выдачу есть.

| Находка | Как обнаружено | Исправление | Повторная проверка |
|---|---|---|---|
| Поиск «макконнелл» не находил «Совершенный код» (автор «Стив Макконнелл») | тест поиска по автору | `lower()` SQLite меняет регистр только у латиницы. Добавлена колонка `search_key` (название и автор), ключи считаются в Python с заменой ё→е | `test_catalog_search_and_availability`: «макконнелл», «ЧИСТЫЙ» находятся. `test_search_ignores_yo_and_case_for_new_items`: «ежик», «ЁЖИК», «елка» находят «Ёжик в тумане», после переименования ключи пересчитаны |
| Журнал при двух событиях в одну секунду мог показать возврат раньше выдачи | тест журнала `[issue, return, issue]` падал нестабильно | во всех списках вторичный ключ сортировки `id` | `test_issue_conflict_return_and_history` 20 прогонов подряд: 20 из 20 |

## Известные ограничения

- Обычная `docker compose up -d --build` без прокси в этой песочнице не проверялась: здесь любой исходящий TLS идёт через перехватывающий прокси.
- Нет очереди, бронирования, продления срока и уведомлений о просрочке.
- Сквозные тесты сбрасывают демо через `/api/demo/reset`: на базе с настоящими данными их запускать нельзя.
- Время в базе хранится в UTC, даты в интерфейсе показываются в часовом поясе браузера. Граница «сегодня последний день» считается по часовому поясу браузера.
- Один экземпляр сервера: SQLite не рассчитан на несколько реплик.
