# Правила работы с проектом 204 Библиотека вещей для офиса

Сервер FastAPI + SQLite (stdlib `sqlite3`, без ORM), интерфейс React + TypeScript + Vite. Один Docker-контейнер, порт `127.0.0.1:8204`.

## Где что находится

- Интерфейс и публичные маршруты — `frontend/src/App.tsx` (вкладки в адресе: `#catalog`, `#item/<id>`, `#mine`, `#overdue`, `#journal`), `frontend/src/ui/Login.tsx`, `frontend/src/api.ts`, `frontend/src/format.ts` (сроки и склонения). API: `/api/auth/*`, `/api/me`, `/api/categories`, `/api/items[/{id}[/copies]]`, `/api/copies/{id}`, `/api/loans[/{id}/return]`, `/api/events`, `/api/health`, `/api/demo/*` (только `DEMO_MODE=1`). OpenAPI — `/api/docs`.
- Предметная логика и хранение — `backend/app/service.py` (правила), `backend/app/main.py` (маршруты, права), `backend/app/web.py` и `auth.py` (вход, сессии, роли), `backend/app/db.py`, `backend/app/migrations/*.sql`.
- Данные, ассеты и демоматериалы — `backend/app/seed.py` (куратор, три сотрудника, 12 вещей, 14 экземпляров, 3 выдачи), `backend/app/synthetic.py N`, `frontend/public/favicon.svg` (собственная), том Docker `library-data`.
- Тесты и документация — `backend/tests/` (pytest), `frontend/src/*.test.ts` (Vitest), `frontend/e2e/` (Playwright), `scripts/container_check.py`, `docs/`.

## Команды и сценарий

- Установка — `docker compose up -d --build`. Для разработки: `backend/.venv` + `pip install -r requirements-dev.txt`, `frontend: npm ci`.
- Запуск и адрес — http://127.0.0.1:8204 (контейнер). В разработке: uvicorn на :8000 и `npm run dev` на :5204.
- Проверки и сборка — `cd backend && python -m pytest`, `cd frontend && npm test && npm run build && npm run e2e` (против контейнера), `python3 scripts/container_check.py --restart`.
- Данные и результат показательного сценария — два сотрудника (`anna`, `boris`, пароль `employee-demo`) одновременно берут `И-203` («Свинтус»): один получает выдачу, второй видит конфликт и обновлённую карточку. После возврата второй берёт вещь. Куратор `curator / curator-demo` видит в журнале выдачу, возврат и выдачу, в просрочках — `К-003` у Анны.

## Инварианты проекта

- Каталог (`items`) и физические экземпляры (`copies`) хранятся отдельно. Наличие считается только по экземплярам без открытой выдачи и без списания. Просрочка вычисляется по `due_at` открытой выдачи, отдельного флага нет.
- Одна открытая выдача на экземпляр гарантируется частичным уникальным индексом `loans_one_open_per_copy ON loans(copy_id) WHERE returned_at IS NULL`. Проверка в `service.issue` нужна для понятного ответа, защита — индекс. Не убирайте его и не заменяйте проверкой в коде.
- Каждая запись — одна транзакция `BEGIN IMMEDIATE` (`db.write_tx`), событие журнала пишется в той же транзакции, что и изменение.
- Автор операции берётся только из сессии. Сотрудник видит и возвращает только свои выдачи, куратор — все. Права (`require_role` в `main.py`) отделены от правил (`service.py`).
- Повторы безопасны: выдача экземпляра, который уже у этого же сотрудника, отвечает 200 без новой записи. Повторный возврат отвечает текущим состоянием, событие `return` не пишется второй раз.
- Конфликт выдачи — 409 `copy_taken` с актуальной карточкой в поле `card`. Интерфейс показывает её вместо устаревшей.
- Поиск без ML: ключи `title_key` и `search_key` считаются в Python (`str.lower`, ё→е). `lower()` SQLite меняет регистр только у латиницы, поэтому не переносите нормализацию в SQL.
- Миграции — только новыми файлами `NNN_*.sql`, применённые не редактировать. Сид и синтетика идемпотентны.
- `/api/demo/reset` удаляет всё, кроме демо: только для демо-базы.
