# 204 · Библиотека вещей для офиса

`office-lending-library` — веб-приложение с сервером. Сотрудник ищет книгу, переходник или настольную игру, видит, есть ли свободный экземпляр, и берёт его на срок. Возвращает сам или через куратора. Куратор ведёт каталог и физические экземпляры, видит просрочки и журнал операций. Выдать один экземпляр двоим одновременно нельзя: это гарантирует уникальный индекс в базе.

Стек: React + TypeScript + Vite (интерфейс), FastAPI + SQLite (сервер). Всё упаковано в один Docker-контейнер с одним портом.

## Первый запуск (Docker)

Требования: Docker с Compose v2.

```bash
docker compose up -d --build
```

Откройте **http://127.0.0.1:8204**. Порт опубликован только на `127.0.0.1`, поэтому библиотека доступна лишь с этого компьютера. При первом старте применяются миграции и создаются демоданные. Готовность — `curl http://127.0.0.1:8204/api/health` → `{"status":"ok",…}`, контейнер становится `healthy`.

| Роль | Логин | Пароль |
|---|---|---|
| Куратор (Ирина Смирнова) | `curator` | `curator-demo` |
| Сотрудники (Анна Петрова, Борис Ли, Вера Ким) | `anna`, `boris`, `vera` | `employee-demo` |

На экране входа есть кнопки демо-входа (только при `DEMO_MODE=1`).

Демоданные: 12 вещей в трёх категориях, 14 экземпляров (`К-001`…`К-005`, `П-101`…`П-105`, `И-201`…`И-204`) и три открытые выдачи. У Анны книга `К-003` просрочена на 4 дня, у Бориса переходник `П-101`, у Веры игра `И-201`.

```bash
docker compose exec app python -m app.seed              # создать, если нет (повторный запуск не дублирует)
docker compose exec app python -m app.seed --reset      # вернуть демо к исходному виду
docker compose exec app python -m app.synthetic 20000   # 20 000 синтетических вещей для замеров
```

Данные хранятся в томе `library-data` (`/data/office-library.sqlite3`) и переживают `docker compose restart` и `docker compose down` + `up`. Полный сброс — `docker compose down -v`.

Если сборка идёт через корпоративный прокси с собственным корневым сертификатом (ошибка `certificate verify failed` на `npm ci` или `pip install`), передайте сертификат необязательным секретом сборки:

```bash
docker build --secret id=extra_ca,src=/path/to/ca.pem -t office-lending-library:local .
docker compose up -d
```

## Демонстрационный сценарий (по ТЗ)

1. Откройте приложение в двух окнах (второе — в режиме инкогнито). В первом войдите как **Анна Петрова**, во втором как **Борис Ли**.
2. В обоих окнах найдите игру «Свинтус» (поиск по названию и автору, фильтр «Категория», флажок «Только в наличии») и откройте карточку. Её единственный экземпляр `И-203` свободен.
3. Нажмите «Взять на 7 дней» почти одновременно в обоих окнах. Выдачу получает один. Второй видит «Этот экземпляр уже выдан другому сотруднику. Карточка обновлена.», и в его карточке `И-203` уже числится выданным.
4. Победитель возвращает вещь («Вернуть» в карточке или во вкладке «Мои выдачи»). Второй сотрудник берёт `И-203`.
5. Войдите как **Ирина Смирнова** (куратор). «Журнал» показывает три операции по `И-203`: выдача, возврат, выдача, с авторами и временем. «Просрочки» показывает книгу у Анны, просроченную на 4 дня, и кнопку «Вернуть» для приёма вещи.
6. Повторный возврат (например, из второй вкладки, открытой до возврата) не создаёт новой записи в журнале: сервер отвечает текущим состоянием выдачи.

## Проверки

```bash
# Сервер: pytest (API, правила, параллельные запросы на настоящем uvicorn, перезапуск на той же базе)
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest

# Интерфейс: Vitest, сборка, сквозные тесты Playwright против запущенного контейнера
cd ../frontend
npm ci
npm test
npm run build
npm run e2e:install              # один раз: Chromium
npm run e2e                      # против http://127.0.0.1:8204 (docker compose up -d)
# замер на 20 000 вещей: docker compose exec app python -m app.synthetic 20000 && npx playwright test e2e/perf.spec.ts

# Контейнер целиком: готовность, входы, 8 параллельных выдач одного экземпляра, повторный возврат, перезапуск
cd ..
python3 scripts/container_check.py --restart
```

Сквозные тесты и `container_check.py` сбрасывают демо через `/api/demo/reset`: этот вызов удаляет все вещи, выдачи и журнал, кроме демо. Не запускайте их на базе с настоящими данными.

## Запуск без Docker (разработка)

```bash
cd backend && . .venv/bin/activate
DEMO_MODE=1 SEED_DEMO=1 uvicorn app.main:app --port 8000 --reload     # API на :8000, база ./data/office-library.sqlite3
cd ../frontend && npm run dev                                           # http://localhost:5204, /api проксируется на :8000
```

Собранный интерфейс без Vite: `npm run build`, затем запуск сервера с `STATIC_DIR=../frontend/dist` → http://127.0.0.1:8000. Сквозные тесты без Docker: `npm run e2e:local` (поднимает uvicorn на :8304 с временной базой, нужен собранный `dist/`).

## Учётные записи

Демо-пользователи создаются сидом. Свои — командой (пароль спрашивается скрыто):

```bash
docker compose exec -it app python -m app.users add maria --role curator --name "Мария Иванова"
docker compose exec -it app python -m app.users add ivan --role employee --name "Иван Орлов"
docker compose exec -it app python -m app.users passwd maria
docker compose exec app python -m app.users list
```

## Переменные окружения

См. `.env.example`: `APP_PORT` (по умолчанию 8204), `DEMO_MODE`, `SEED_DEMO`, `COOKIE_SECURE`. Внутри контейнера — `DB_PATH=/data/office-library.sqlite3`, `STATIC_DIR=/app/static`. Секретов нет: сессии — случайные токены в базе, пароли хранятся как PBKDF2-SHA256.

## Где что лежит

| Путь | Назначение |
|---|---|
| `backend/app/main.py` | маршруты API, проверка прав, раздача интерфейса |
| `backend/app/service.py` | правила: каталог, поиск, наличие, выдача и возврат в транзакции, просрочки, журнал |
| `backend/app/web.py`, `auth.py`, `users.py` | вход, сессии, роли, консоль учётных записей |
| `backend/app/db.py`, `backend/app/migrations/` | SQLite, транзакции `BEGIN IMMEDIATE`, миграции |
| `backend/app/seed.py`, `backend/app/synthetic.py` | демоданные и синтетика |
| `backend/tests/` | pytest |
| `frontend/src/` | интерфейс: каталог, карточка вещи, мои выдачи, просрочки, журнал |
| `frontend/e2e/` | Playwright |
| `scripts/container_check.py` | проверка запущенного контейнера |
| `Dockerfile`, `compose.yaml`, `.env.example` | контейнер и запуск |
| `docs/` | карточка, архитектура, приёмка, ассеты, исходное ТЗ |
